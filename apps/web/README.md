# FeeStrip web application

React/Vite/TypeScript. Run from repository root after the lead-managed dependency install:

```sh
pnpm --filter @feestrip/web dev
pnpm --filter @feestrip/web build
pnpm --filter @feestrip/web test
```

The default `main.tsx` passes an explicit `FixtureAdapter` to the exported `App`. Every amount and transaction in this mode is visibly a deterministic fixture; it never requests signatures or invents transaction hashes. Tests cover UI behavior, not a production wallet signing interface or live protocol acceptance.

`types.ts` exports the integration boundary. All claim quantities (supply, inventory, holdings, action amounts) use 18-decimal integer base units. USDC balances/prices use 6-decimal integer base units; `askMicros` is USDC per one whole claim. The earning endpoint is a block, while offer/quote expiration fields are timestamps. `amounts.ts` parses user input and rounds purchase cost upward to the next USDC base unit. Payout presentation floors the original-Q proportion.

The viem chain adapter implements the shared ABI boundary. It supplies `load`, `connect`, `execute`, optional `switchNetwork`. `execute` must validate current chain state, wait for a real receipt, and return only a genuine transaction hash. The UI reloads after execution. Historical Graph data is not a settlement authority. The live adapter does not expose fixture controls or silently fall back to fixtures.

Design source, immutable concept captures, independent critique, reference notes and browser evidence are in `docs/design/`. Self-hosted DM Sans and Manrope include their SIL Open Font Licenses. All application code and design artifacts in this increment were generated by Codex, reviewed by the integration lead; no human design review is claimed.

## Direct onchain mode

`ChainAdapter` now validates deployment code, chain ID and immutable contract bindings; reads NFT metadata and fixed series terms at one block; discovers Aqua `Shipped` events; and rebuilds every candidate order through the deployed FeeStrip market. Only a byte-identical strategy for the current series state qualifies. Actual maker balances, allowances and Aqua virtual allocations cap executable quantity. The review carries the strategy hash, exact ratio, maximum USDC, minimum claims and expiry into the transaction.

Use `VITE_DATA_MODE=local` or `testnet` with `/deployment.json` generated by the root setup scripts. There is no fixture fallback in either mode. Standard wallet access uses the injected EIP-1193 provider. Local browser regressions additionally require **both** `VITE_ENABLE_TEST_WALLET=true` and `?wallet=seller|buyer|holder`; these unlocked RPC accounts are restricted to loopback chain 31337. No private key is bundled or read by the application. These tests prove application transactions, not a production wallet's signing interface.

The optional `readAnalysis` adapter method requests `/api/analysis` using claim quantity in 18-decimal base units and the **total purchase cost** plus optional execution cost in 6-decimal USDC units. The UI exposes common source block/hash, source identities, lag, coverage, occupancy and caveats. Missing or invalid sources remain unavailable and never create synthetic chart data or settlement authority.

A separate serial browser suite resets the dedicated local node. Run from repository root with Anvil on 8545, after contract dependencies and builds are available:

```sh
node_modules/.bin/playwright test -c apps/web/playwright.chain.config.ts
```

It starts the local app on 4175, calls root `reset-and-seed.mjs --reset`, funds and accepts an offer in the browser, publishes an Aqua quote, trades claims, invokes the root maturity/witness helper, captures, returns the NFT before proof, submits the retained witness and redeems all holders and residual fees. The fixture suite stays on 4174. Set `FEESTRIP_REPO_ROOT` only when running the browser suite from an isolated worktree against root-owned setup scripts; normal checkout and CI need no path override. Raw receipts and integer balances are written to `docs/evidence/browser-chain-lifecycle.json`; screenshots and traces are Playwright attachments.

## Two-wallet funded sale

`#pin/<canonical-NFT-ID>` imports a canonical position using configured-chain reads, including for disconnected visitors and external buyers. `#pin/<NFT-ID>?offer=<offer-ID>` selects one exact funded offer; it never silently switches to a higher-paying offer. The owner approves and accepts; a separate buyer funds. Self-funding is intentionally disabled in the interface because it does not produce external proceeds.

The editable test offer starts at 1 USDC, 80% of fixed original Q=10,000 claims, and 600 blocks ahead. Payment is limited to 1,000 test USDC; the user reviews exact payment, share, original Q, seller, position range/liquidity, endpoint and UTC deadline. More than 32 blocks and 60 seconds must remain after any allowance transaction. Changing positions resets the draft; background refresh leaves edited values and open reviews untouched. The reviewed position commitment is included in the new `fundOffer(...,bytes32 expectedPositionCommitment)` calldata, with preflights before and after approval. This requires the corresponding reviewed-position FeeStrip deployment and generated ABI.

Public funding and acceptance require a fresh `/api/operations` response bound to the exact deployment, with `protocol`, `keeper`, `retention`, and `replication` checks all ready. Observations older than 60 seconds or more than five seconds in the future fail closed. Local-chain and explicitly labelled fixtures are exempt from this operations gate. The gate controls new commitments, never existing refunds, proof allocation or payouts. Vite proxies the route through `FEESTRIP_OPERATIONS_ORIGIN` (default loopback port 8789).

Connected, visible pages refresh every 15 seconds and on focus/visibility/wallet events. Transaction simulation and ETH gas checks run before each signature. Browser receipts are scoped to account, chain and FeeStrip address, preserve approval versus funding, and link an actual funded offer to seller review. A successful transaction closes its review even when the follow-up RPC read fails. An unresolved broadcast blocks additional app submissions until its receipt resolves; cancellation/replacement in the wallet can be reconciled by pasting its confirmed hash. Public signed transaction bytes authenticate the original sender/nonce after a browser restart; byte/hash mismatch, a different sender/chain/nonce, an unconfirmed replacement or an orphaned receipt cannot clear the guard. Changed to/value/input is labelled as a different action and never as successful completion of the original action. If original signed bytes were not retained and the RPC no longer provides them, reconciliation remains blocked rather than trusting editable local metadata. Local browser storage is a convenience, never proof or payout authority.

Verification includes the existing complete local financial lifecycle plus a second, previously unlisted canonical NFT: disconnected view, separate buyer funding exact small terms, receipt reload, exact cancellation refund, seller acceptance from its offer link, and automatic counterparty refresh. These are local-chain tests, not public wallet acceptance. Run them with an isolated Anvil and the pinned witness-validator Python environment:

```sh
FEESTRIP_PROOF_PYTHON=/tmp/feestrip-proof-venv/bin/python \
LOCAL_RPC_URL=http://127.0.0.1:8561 \
FEESTRIP_TEST_WEB_PORT=4292 FEESTRIP_TEST_RECOVERY_PORT=8792 \
pnpm exec playwright test -c apps/web/playwright.chain.config.ts
```
