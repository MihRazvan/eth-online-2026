# Authenticated historical growth (Codex, 2026-09-11)

Use `HistoricalFeeVerifier` with an immutable canonical PoolManager, its deployment-time codehash, an immutable chain ID, and `BlockHashCheckpoints`. The caller passes its frozen endpoint, pool, signed ticks and USDC currency selector; it computes full-precision entitlement from the frozen liquidity and cleared baseline. The verifier never accepts a caller-selected root or amount. The escrow must validate the canonical position and freeze those inputs; the verifier intentionally supports growth reads shared by different positions in the same pool/range.

`keccak256(RLP header)` must equal this chain's `BLOCKHASH(N)` or its immutable cached value. The header supplies the state root and must contain N. One EIP-1186 account proof authenticates the manager's storage root and exact codehash. A deduplicated storage multiproof proves slot0 (including stored signed tick), the selected global fee growth, and both boundary outside values. Slots derive internally from canonical v4 `_pools` mapping slot 6, pool offsets 1/2, and ticks mapping offset 4 with tick-field offsets 1/2. Arithmetic matches v4's unchecked uint256 growth semantics. An absent initialized-pool slot is rejected. Authenticated storage absence means zero; missing or invalid witnesses revert.

Any address can checkpoint N in blocks **N+1 through N+256 inclusive**. Anyone can also prove and permanently cache growth, keyed by the complete endpoint/pool/range/currency tuple, amortizing its cost across compatible series. Cached values cannot be overwritten or administered. Cache contracts must be deployed from the reviewed source; deploying a verifier with an arbitrary fake cache is invalid deployment configuration. The integration should deploy its checkpoint contract itself or verify its code.

A missed hash window without either cached hash or authenticated growth **permanently prevents this verifier from allocating that endpoint**. No timeout, server signature, administrator or sweep fallback exists. This is a concrete liveness bound, not a claim that a free public RPC service guarantees availability. Capture and original-NFT return must still remain possible in the separate lifecycle contract. Public-node proof retention is a separate, tighter operational concern described in evidence. Production activation needs reliable witness capture and checkpoint submission infrastructure; that operational acceptance is not established here.

Rejected: trusting `eth_getStorageAt`, The Graph, a server signature, or accepting an arbitrary state root. Those alter the settlement trust model. EIP-2935's longer window could improve checkpoint liveness but requires chain/deployment verification; it is not assumed by this implementation. A ZK proof may lower onchain gas but has no validated compatible implementation in this lane. Polytope's existing MPT verifier was selected over writing a new trie decoder; code and Apache-2.0 license are pinned unchanged in `contracts/lib/proof-polytope/SOURCE.json`.
