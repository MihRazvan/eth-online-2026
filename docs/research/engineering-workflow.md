# Engineering workflow: selective skills, reproducible evidence

Research date: 2026-09-11. Repository baseline: `22a8996`. Author: OpenAI Codex engineering specialist. Scope: read-only source evaluation; no packages installed, downloaded scripts executed, hooks enabled, global settings changed, or services purchased. Recommendations prioritize a usable financial product. They do not establish public-chain acceptance or a security audit.

Keep FeeStrip's native agents, isolated worktrees, shared acceptance ledger, and independent review. Add narrowly selected review procedures where they can catch a demonstrable failure. The immediate gap is operational evidence: actual wallet behavior, provider-backed history, recovery from interrupted transactions, and proof availability. A larger orchestration stack does not supply those capabilities.

The [skills.sh leaderboard](https://www.skills.sh/) displayed approximately 705.6K installs for Vercel React guidance and 831.9K for agent-browser during inspection. These are discovery signals, not controlled quality measurements. The installed Find Skills instructions suggest popularity thresholds; this evaluation instead checks domain fit, source ownership, update history, execution surfaces, and measurable results. Six named repositories were inspected through GitHub metadata, five recent commits, recursive file trees, and selected files at immutable revisions.

## What is already working

The [tooling record](../evidence/tooling.md) documents source-only use of StreamingFast development/EVM and Graph development guidance. The [design record](../design/WORKFLOW.md) documents Impeccable, selected React guidance, three rendered directions, and independent visual critique. Those reviews corrected economically misleading copy, missing original-supply context, unavailable-price scenarios, and the placement of technical detail. This is evidence of useful review, without claiming that a skill alone caused the improvements.

The [status ledger](../STATUS.md) records passing local and hosted checks, a complete local browser transaction lifecycle, static-analysis triage, and an incorrect-denominator mutation kill. The [data review](../evidence/data-review.md) independently reproduced mixed-fork attribution and identified source-identity and Graph query defects. The browser integration rerun exposed a same-URL login assumption that ordinary fixture checks missed. Preserve these executable reproductions and their scope; test totals are a weaker signal than which failure each test detects.

The current [lifecycle campaign](../../contracts/test/FeeStripLifecycleInvariant.t.sol) already starts from unfunded NFTs, exercises dynamic transitions, and records successful actions; an older review described the earlier, narrower campaign. Existing Foundry, Slither, mutation, and review work should retain its actual attribution. No inspected record establishes prior application of the Uniswap or Trail of Bits candidates as named skills.

## Native coordination versus another framework

Official [Codex subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) recommends bounded independent work and cautions that concurrent writing increases coordination costs. [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees) provide separate checkouts; they do not isolate a shared Anvil process, generated deployment file, port, or database. FeeStrip encountered that distinction during browser integration. Explicit resource ownership is therefore as important as file ownership.

Keep each assignment's base SHA, owned paths, input/output interface, acceptance command, and evidence destination. Give shared ABIs, lockfiles, and pushes one owner. Reserve a dedicated chain/port/database for destructive tests; stop stale servers before integrated reruns. Have a reviewer reproduce economically meaningful failures independently, then have the lead rerun the committed test from the integrated checkout. Persist those results in the existing ledger, not several competing plans. Official [skill documentation](https://learn.chatgpt.com/docs/build-skills) supports loading detailed instructions only when needed; avoid making every task ingest the entire catalog.

[OpenSpec](https://github.com/Fission-AI/OpenSpec) supplies proposal/spec/design/task artifacts; [Spec Kit](https://github.com/github/spec-kit) supplies principles, planning, tasks, implementation, and convergence workflows. These could help a team lacking durable requirements. FeeStrip already has the economic contract, decisions, ownership ledger, and executable evidence, so migration currently duplicates authoritative artifacts. Defer both rather than stacking their workflows. The [OpenAI Agents SDK](https://developers.openai.com/api/docs/guides/agents/sdk) builds agent runtimes in application code; introducing one solely to coordinate this repository would create another software system to operate. Revisit only if repeated measured coordination failures remain after explicit ownership, or a real product feature requires an agent runtime.

## Proposed measurable experiments

These are prospective experiments, not results from this research pass.

1. **Review effectiveness:** replay three historical defect diffs—incorrect denominator, stale market state after callback, and mixed-fork attribution—in disposable checkouts. Give independent reviewers the relevant skill and a fixed review window without the fixes. Measure reproduced defects, false positives, time, and assumptions. Retain guidance that improves detection without weakening original acceptance criteria.
2. **Lifecycle properties:** reuse the dynamic campaign and its counters instead of rebuilding completed coverage. Compare it with the genuine-verifier lifecycle: inject malformed or unavailable witnesses, repeated submission, and interrupted collection/return sequences in disposable tests. Require unchanged liabilities on failed proof, independent NFT return after capture, reserve conservation, and original-Q payouts. Report seeds, successful transitions, and counterexamples; distinguish the campaign’s endpoint stub from real-verifier evidence.
3. **Source recovery:** once access arrives, consume a bounded real block interval, interrupt and restart from its cursor, and compare canonical output to uninterrupted execution. Exercise duplicate delivery and undo with deterministic retained fixtures separately. Require identical final rows, no double counting, explicit finality/coverage, and unavailable analysis when source identities disagree. Provider access is a dependency, not a silently skipped success.
4. **Wallet and buyer comprehension:** use an actual injected wallet for rejection, repricing/replacement, network change, refresh, and return after maturity; keep the local unlocked-wallet regression distinct. In observed user sessions, ask participants to identify original NFT rights, the native USDC leg, original Q, exact cutoff, and proof-delay behavior. Target at least four of five correct unaided answers and no confusion between hypothetical net income and an executable price; revise the interface where observed errors cluster.
5. **Coordination cost:** track the next three coherent increments: overlapping edits, shared-resource collisions, integration rerun failures, review time, and elapsed time to verified commit. Target zero ownership collisions and a documented resolution for each failure. Consider a framework only if the record identifies a persistent problem it specifically solves.
